# 从共同源码到正式站

GitHub 的 `main` 管理共同源码与公开内容修订。项目所有者保管生产账号工程、来源审查证据、学生数据和发布权限。朋友可在自己的 clone 运行完整站点、开发功能、修题并交付 PR，无需生产凭证。

## 拉取固定提交

PR 通过另一人评审并合入 `main` 后，所有者在自己的源码 clone 拉取：

```sh
git status --short --branch
git switch main
git pull --ff-only
git rev-parse HEAD
```

有本地工作时先保存到任务分支，不强制覆盖。记录固定提交后再组装候选。生产大工作区中的模板副本是发布整合对象，不是另一条独立开发主线；紧急修复也应回到本仓分支和 PR。

## 源码与内容分别核对

源码改动从固定提交按明确文件清单整合，包括生成器、模板、共享运行时及其必要工具。先比较目标现有字节 / SHA，发现目标另有修改时停止覆盖并合并；不整目录复制另一个项目，不夹带历史运行文件。

公开 canonical 是去敏协作副本，生产 canonical 还含来源与审查证据。两者按 `question_id` 和具体材料 occurrence 生成字段级 diff，核对预期旧值、建议新值与 PR 依据；只采纳经审的教学字段。生产 `source`、审核记录和资源 provenance 不能被公开投影整包覆盖。

特别检查答案 / 解析、评分版本、迁移和资源引用。公开导出已去掉内部元数据和来源水印，评分 hash 可以与生产不同；不能把这种差异误判为所有相关题都需要改答案，也不能以公开 hash 直接替换生产评分证明。

仓库提供只读回流计划工具。先将改动提交到任务分支或已合并的主线；工具固定读取当前 `HEAD`，要求没有 tracked 修改和非忽略的 untracked 文件。无需先合并 PR 即可准备审查计划。示例路径替换为自己的生产内容工作区：

```sh
python3 scripts/prepare-workspace-update.py \
  --workspace /path/to/private-workspace \
  --base-ref initial-import
```

默认结果写入本 clone 的 `build/workspace-update.json`，报告记录 `baseCommit` 和 `headCommit`。工具比较基线 ref 与已提交 `HEAD`，列出全部变化文件（包含新增 / 删除）、8 个既有核心源码的旧值核对、按题目 ID / 字段的建议修改、材料元数据与题目顺序 / 成员变化，以及 registry、迁移和素材的人工核对项。新增源码或超出既有整合清单的文件也会列明，不能当作已自动整合。它只读取生产工作区，**不会修改生产文件，也不会构建或发布生产候选**。生产工作区必须与源码 repo 分离；输出仅允许在本 repo 真实的忽略 `build/` 目录内，拒绝符号链接和与生产工作区重叠的位置，不提交计划中涉及的私有信息。

计划不是已应用结果。先检查 Git 状态与报告中的提交身份；有未提交改动时先提交或移至另一任务分支，不存在读取 dirty 工作区的计划模式。已成功回流过的修改不要再次盲目应用；可将上次已整合提交作为后续基线，仍逐项检查目标旧值。维护者处理冲突、保存原件，并记录采纳与拒绝。去敏造成的旧值差异需要人工核对，不能改成自动覆盖。没有核实的内容留待复核，不靠猜测批量改题或旧成绩。

## 构建生产候选

使用新的独立候选目录，将固定提交的核心与核实后的生产 canonical、registry、迁移和必要图组合，再重新生成站点。公开 `build/site/` 可用于开发验收，但尚无生产登录包装；`build/site-preview/` 打开了全部发布开关，只供评审；`build/demo/` 仅含原创 fixture，三者都不是可直接上传的生产包。

## 发布开关

导入基线（34 个套题、3 个专项、11 个题型页，1,752 题，48 个路由）之后加入的内容由仓库根目录的 `sat-release.json` 控制：

| 开关 | 控制的内容 | 关闭时 |
| --- | --- | --- |
| `expandedQuestionBank` | registry 中带 `releaseGate: expandedQuestionBank` 的 70 份材料（2,302 道新题），以及题型页因此增加的题 | 不构建这些材料，题型页的题目列表、存储键与基线相同 |
| `fixedMockExams` | registry 中 `examEligible` 的固定两模块模考（目前 19 套，其中有 22–27 题的缩短模块和重新开放的旧 34 卷） | 页面不出现模考入口，`?mode=exam` 只显示「模考暂未开放」，不读模考记录 |
| `wordExplanations` | AI 草稿的词汇解释（1,168 词，`basis: ai_draft`）、词汇表和生词本 | 页面不带任何词汇数据，没有「词汇」入口和「加入生词本」按钮 |
| `walkthroughs` | AI 草稿的核心题中英讲解（345 题，`basis: ai_draft`） | 页面不带讲解；解析完整度按原有解析计算 |

构建器只认这个文件：文件不存在时四个开关都视为关闭，所以没有这个文件的工作区构建出来的也是基线。开关之间相互独立，例如只开模考时，基线里能成为模考的只有旧 34 卷。`python3 scripts/build-site.py --preview-all` 在 `build/site-preview/` 构建全部打开的版本，供所有者先看再决定。

打开 `expandedQuestionBank` 之前还要处理迁移契约：题型页变大后存储键改变，构建器会把基线题型页的旧键作为迁移写进候选的 `sat-practice-migrations.json`（页面按题目 ID 恢复停留位置，答案照常合并），而生产门禁按 `scripts/sat_runtime_metadata.py` 中批准的迁移文件哈希核对，会因为多出这 8 个旧键而拦下候选。这是有意的：所有者审核这些迁移后，更新仓库里的迁移文件和批准哈希，再开启开关。

验证默认构建：`python3 scripts/build-site.py` 输出应为 1,752 题、48 个路由、0 套模考、无开启的开关；`node scripts/verify-sat-release-and-isolation.mjs --release-root build/site --preview-root build/site-preview` 在浏览器里核对这些内容不出现。

至少核对材料 / 题目数量、稳定 ID / 路由、答案与解析、评分 / 迁移、资源可达及来源限定。交互变化验证选择 / 改选 / 提交、主动 Reveal、刷新恢复、owner 切换、重置 / 重做、迟到同步和移动端。测试使用专用合成状态；真实账号与跨设备测试有独立验收边界。

生产工程负责保留登录保护与宿主协议。在包装后的最终候选重新验证，绑定本轮源码和内容摘要。旧报告、旧截图或历史 PASS 不能为新候选背书。

## 发布边界

仓库不配置生产 deployment workflow。`push` 与 PR 只保存和检查共同开发成果；合入 `main` 不直接更新学生站点。所有者核对具体候选后，另行发起正式静态发布。

生产发布需要新的冻结候选、匹配门禁和 dry-run。历史 run 的发布脚本与证明绑定当时字节，不可再次执行充当通用命令；通用发布器也要求干净 publisher Git 身份、显式 bundle 和匹配证明。SAT-only 更新仅限 SAT 静态对象，不部署云函数或修改学生数据。

每次发布保留源码 commit / tag、数据和候选摘要、审查结果、dry-run、实际发布、线上 HTTP / 字节核验、必要真实浏览器检查与回滚位置。将“代码合并”“本地验证”“正式发布”“线上验收”分别记录，不将其中一项当作其他项已完成。

## 回滚与之后的开发

回滚使用上一份经过核验的发布包与原件，核对线上冲突后执行受控恢复；不改写共享 Git 历史，不清空学生学习记录。回滚后仍在仓库修正原因，再经 PR 提交下一版。

公开 release 保留去敏的行为变化、固定提交和验证摘要；生产凭证、学生记录与完整私有证据留在受控环境中。后续开发继续从更新后的 `main` 开分支，避免产生只留在某台机器的改动。
