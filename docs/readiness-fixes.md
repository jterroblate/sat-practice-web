# 初始导入后的开发准备修订

本记录描述公开协作仓库的初始化补强，不是生产更新报告。首次 `docs/content-export.json`、`initial-import` 基线与生产来源 / 审查证据继续保留；本轮不覆盖原生产工作区，不部署页面、云函数或改写学生记录。

## 当前素材清单参与干净构建测试

全库测试的临时 checkout 改从 `assets/content-resources.json` 复制当前题图。之前误用首次导入报告中的资源列表，会使按文档新增 / 替换图片的 PR 在正常构建后仍因测试缺图失败，也会阻止删除已退休的旧图。

当前清单随图片和引用一起评审；首次导入报告只保留历史导出事实。新增和退休资源的回归覆盖这一边界，不能通过改写首次报告来让测试通过。

## 共享题目 ID 的评分内容对齐

公开题库的 `jun2025_apac_a_08` 同时出现在 Partial 与 Full 材料中，但保留了不同的解析措辞，导致共享记录绑定不同评分 hash。本轮将 `08-2025-06-apac-a-full.json` 该题既有的完整学生解析原样同步到 `06-2025-06-apac-a-partial.json` 的同 ID 记录；题干、选项、答案与公共 ID 不变。

这是公共开发副本内部的一致性修订，不是一轮新答案审核，也不表示生产内容或旧成绩已调整。测试比较同 ID 的 `grading_revision()`，以后修改共享题目时须核对全部 occurrence。公开内容回流生产仍要检查私有旧值、证据和评分 / 迁移方案。

## 首次导出工具拒绝覆盖协作内容

`export-current-content.py` 仅服务首次受控导入。已经存在导入报告或目标内容的 checkout 不能再次导出覆盖；日常构建使用 `build-site.py` / `build-demo.py`，修题和改功能通过当前仓库分支 / PR。

首次导入的哈希与出处事实继续保留。后续内容变化另由对应提交和 PR 说明，不修改历史记录使新内容看起来像最初导出。

## 只读回流计划固定提交并保护输出位置

`prepare-workspace-update.py` 要求干净 Git 状态，固定当前 `HEAD`，将 `baseCommit` / `headCommit` 写入计划；不接受混入未提交文件的隐式候选。输出限制在本 repo 真实的 `build/` 内，拒绝符号链接或与生产工作区重叠的输出路径，避免计划文件写入生产位置。

计划补充完整变化文件清单、增删文件、材料元数据、题目顺序 / 成员，以及 registry、迁移和素材核对项。8 个既有核心文件之外的变化也显式列明并要求人工核对。该工具生成审查计划，既不应用 JSON patch，也不复制源码或执行发布。准确命令见 [production-handoff.md](production-handoff.md)。

## 协作和验证记录

两人开发继续使用任务分支、PR、`checks` 与另一位有权限开发者批准。主线不额外要求批准者不能是最后推送修订的人，保留新提交使旧批准失效的规则。尚未取得 write 权限的朋友可从自己的 fork 发 PR，由所有者评审；对等相互评审须先完成权限邀请。

本轮属于所有者明确授权的初始化修复。初始化整合的实际 PR、CI 与保护设置操作以对应 GitHub 记录为准；本文件不声明已经获得另一位真人批准，也不预先记为测试通过。后续普通开发继续执行一人评审约定，不以初始化修复作为绕过协作规则的依据。
